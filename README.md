# Выдыхай

Лендинг для подростков о вреде сигарет и вейпов с формой заявки, CRM-админкой с воронкой, учётом расходов по чекам и уведомлениями в Telegram.

- `index.html` — лендинг с формой заявки
- `admin.html` — админка (адрес `/admin`, вход по паролю): вкладка «Клиенты» (доска по этапам, карточка клиента, ручное добавление) и вкладка «Расходы» (чеки, итоги месяца)
- `app.html` — Telegram Mini App «Запись на консультацию» (адрес `/app`, открывается из меню бота)
- `api/app.js` — для Mini App: свободные слоты на 14 дней и запись (проверяет подпись initData Telegram)
- `api/expense-scan.js` — распознаёт фото или PDF чека через Gemini (`gemini-3.8-flash`), ничего не сохраняет
- `api/expenses.js` — расходы: список и итоги за месяц, сохранение с оригиналом в приватный bucket, временная ссылка на оригинал
- `api/lead.js` — принимает заявку с сайта (источник «Сайт», этап «Новая»), сохраняет в Supabase, шлёт сообщение в Telegram
- `api/login.js` — вход в админку
- `api/leads.js` — клиенты: список для доски, карточка с историей, ручное добавление, смена этапа и заметок
- `api/invoices.js` — счета: выставить (PDF + отправка в Telegram), список счетов клиента, ссылка на PDF, отметка оплаты
- `api/_invoice-pdf.js` и `api/_fonts/` — сборка PDF счёта (pdf-lib, шрифт Manrope с кириллицей)
- `supabase.sql` — полная схема для новой установки (таблицы `leads` и `lead_stage_history`, триггер истории)
- `migrations/001_crm.sql` — перевод уже работающей базы на CRM-воронку
- `migrations/002_expenses.sql` — таблица расходов и приватный bucket `receipts` для оригиналов чеков
- `migrations/003_telegram.sql` — источник «Telegram», поля записи на консультацию, защита слотов от двойной записи
- `migrations/004_invoices.sql` — этап «Оплачено», источник «Голос», таблица `invoices` и приватный bucket `invoices`

Этапы воронки: **Новая → Связались → Записан на консультацию → Консультация проведена → Оплачено**, плюс **Отказ**.
История этапов пишется триггером в базе: при создании клиента и при каждой смене этапа.

Ключей в коде нет. Все они задаются в Vercel как переменные окружения.

## Запуск: пошагово

### 1. Supabase
1. Зайдите на supabase.com → **New project**. Регион лучше выбрать Frankfurt.
2. Откройте **SQL Editor → New query**, вставьте содержимое `supabase.sql` и нажмите **Run**.
   Если база уже работала до CRM (таблица `leads` есть), вместо этого выполните `migrations/001_crm.sql` — см. раздел «Обновление до CRM».
3. Откройте **Project Settings → API Keys** (или Data API) и скопируйте:
   - **Project URL**: это будет `SUPABASE_URL`;
   - **Secret key** (`sb_secret_…`) или старый **service_role**: это будет `SUPABASE_SERVICE_KEY`.
   Ключ `anon` / `publishable` не подходит.

### 2. Telegram-бот
1. Напишите в Telegram боту **@BotFather** команду `/newbot` и придумайте имя. Он пришлёт токен: это `TELEGRAM_BOT_TOKEN`.
2. Найдите своего нового бота и нажмите **Start** (или напишите ему любое сообщение).
3. Откройте в браузере `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите `"chat":{"id":123456789`. Это число — `TELEGRAM_CHAT_ID`.

### 3. Пароль админки и секрет
- `ADMIN_PASSWORD`: придумайте надёжный пароль для входа в `/admin`.
- `SESSION_SECRET`: длинная случайная строка. Её можно получить в PowerShell:
  ```powershell
  $b = New-Object byte[] 32; [Security.Cryptography.RNGCryptoServiceProvider]::new().GetBytes($b); [Convert]::ToBase64String($b)
  ```

### 4. GitHub
1. На github.com нажмите **New repository**, назовите его `vydyhai` и создайте.
2. Нажмите **uploading an existing file** и перетащите все файлы и папки `api` и `migrations` из папки проекта.
3. Нажмите **Commit changes**. Файлов `.env` с настоящими ключами в репозитории быть не должно.

### 5. Vercel
1. На vercel.com выберите **Add New → Project** и импортируйте репозиторий `vydyhai`.
2. В поле **Framework Preset** выберите **Other**. Сборка не нужна.
3. В разделе **Environment Variables** добавьте семь переменных:
   `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `ADMIN_PASSWORD`, `SESSION_SECRET`, `GEMINI_API_KEY`.
   `GEMINI_API_KEY` берётся в Google AI Studio → **Get API key**. На бесплатном тарифе Google может использовать
   отправленные чеки для улучшения своих продуктов.
4. Нажмите **Deploy**. Если переменные меняли позже, нужно сделать **Deployments → … → Redeploy**.

## Обновление до CRM (база уже работает)
Порядок важен: **сначала SQL, потом код**. Если загрузить код раньше, заявки с сайта перестанут сохраняться,
пока не выполнена миграция.
1. Supabase → **SQL Editor → New query** → вставьте весь `migrations/001_crm.sql` → **Run**. Должно быть «Success. No rows returned».
2. Загрузите на GitHub изменённые файлы (см. шаг 4 выше) — Vercel сам сделает новый деплой.

Старые статусы переносятся так: «новая» → Новая, «в работе» → Связались, «закрыта» → Консультация проведена.
В истории таких клиентов есть пометка «перенесено из старого статуса …» с датой миграции.

## Обновление: модуль «Расходы»
Снова **сначала SQL, потом код**.
1. Supabase → **SQL Editor → New query** → вставьте весь `migrations/002_expenses.sql` → **Run**.
2. Vercel → **Settings → Environment Variables** → добавьте `GEMINI_API_KEY`.
3. Загрузите код на GitHub — Vercel сам сделает новый деплой (в нём уже будет новая переменная).

Фото чека браузер уменьшает до 2000 px и пересохраняет в JPEG, PDF принимается до 3 МБ — так запрос
укладывается в лимит Vercel 4,5 МБ. Если исчерпан бесплатный лимит Gemini, админка пишет «Попробуйте позже»;
дневной лимит Google обнуляется в полночь по тихоокеанскому времени.

## Обновление: запись через Telegram Mini App
Снова **сначала SQL, потом код**. Новых переменных окружения нет — используется `TELEGRAM_BOT_TOKEN`.
1. Supabase → **SQL Editor → New query** → вставьте весь `migrations/003_telegram.sql` → **Run**.
2. Загрузите код на GitHub, дождитесь деплоя на Vercel.
3. Привяжите Mini App к боту в **@BotFather**:
   - `/mybots` → выберите бота → **Bot Settings** → **Configure Mini App** → **Enable Mini App** →
     отправьте адрес `https://vydyhai.vercel.app/app`;
   - `/mybots` → бот → **Bot Settings** → **Menu Button** → **Configure menu button** →
     отправьте адрес `https://vydyhai.vercel.app/app`, затем название кнопки `Записаться`.

Слоты: каждый день, начало в 10:00–17:00 по Кишинёву, по часу, на 14 дней вперёд (сегодня — не позже чем за час).
Занятое время больше не предлагается; двойную запись дополнительно блокирует уникальный индекс в базе.

## Проверка по заданию
1. Откройте сайт по публичной ссылке Vercel с телефона. Отправьте пустую форму: должна появиться ошибка. Отправьте заполненную: должно появиться подтверждение.
2. Откройте Supabase → **Table Editor → leads**. Там будет заявка с датой, этапом «Новая» и источником «Сайт». В `lead_stage_history` — строка с `to_stage` = «Новая».
3. Откройте `/admin` в режиме инкогнито: без пароля клиенты не видны. После входа видна доска из пяти колонок по этапам; карточку можно перевести на другой этап списком или перетаскиванием, открыть по клику, отредактировать заметки и посмотреть историю этапов.
4. Проверьте Telegram: после заявки бот присылает сообщение со всеми данными.
5. Вкладка «Расходы»: добавьте фото чека → на экране проверки поля совпадают с чеком → «Сохранить» → запись и итоги месяца,
   «Оригинал» открывает файл. Фото без документа → сообщение «Похоже, это не чек…», в Supabase ничего не появилось
   (ни строки в `expenses`, ни файла в Storage → `receipts`).
6. Telegram: кнопка меню «Записаться» открывает `/app` на весь экран с «Привет, {имя}!»; после записи в CRM
   появляется клиент с источником «Telegram» на этапе «Записан на консультацию» и датой консультации.
   `/app` в обычном браузере показывает только «Откройте приложение в Telegram».
7. Поищите на GitHub в репозитории `sb_secret`, `eyJ`, `AIza` (начало ключа Gemini) и токен бота. Ничего не должно найтись.

## Обновление: счета на оплату
Снова **сначала SQL, потом код**. Новых переменных окружения нет.
1. Supabase → **SQL Editor → New query** → вставьте весь `migrations/004_invoices.sql` → **Run**.
2. Загрузите код на GitHub, дождитесь деплоя. Vercel сам поставит `pdf-lib` из `package.json`.
3. Проверка: карточка клиента → **Выставить счёт** → PDF приходит клиенту в Telegram (если он из Mini App) или вам в чат с пометкой «Клиенту не отправлен». **Отметить оплату** переводит клиента на этап «Оплачено».
