# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## О проекте

«Выдыхай» — лендинг для подростков о вреде сигарет и вейпов. На нём есть форма заявки, CRM-админка с воронкой, учёт расходов по чекам (распознавание через Gemini) и уведомления в Telegram. Хостинг на Vercel, данные хранятся в Supabase. Подробная инструкция по развёртыванию (Supabase → Telegram-бот → GitHub → Vercel) и чек-лист проверки лежат в `README.md`.

## Сборка и запуск

- Сборки, линтера, тестов и npm-зависимостей нет. `package.json` нужен только для `"type": "module"`, чтобы `api/*.js` работали как ES-модули.
- На Vercel выбран Framework Preset **Other**. HTML отдаётся как статика, `api/*.js` работают как serverless-функции Node (`export default handler(req, res)`). `fetch` и `node:crypto` встроенные.
- Без переменных окружения API не работает: `env()` в `_lib.js` бросает ошибку. Нужны семь переменных: `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `ADMIN_PASSWORD`, `SESSION_SECRET`, `GEMINI_API_KEY`. Настоящие значения задаются только в настройках Vercel. В `.env.example` хранится лишь образец без значений.
- Полная схема БД для новой установки лежит в `supabase.sql`. Изменения для уже работающей базы лежат в `migrations/NNN_*.sql`. И то и другое выполняют вручную в Supabase SQL Editor, причём миграцию — до загрузки кода, который на неё опирается. Меняя схему, обновляйте оба файла.
- Это git-репозиторий, связанный с GitHub (`origin/main`). Push на `main` сразу запускает деплой на Vercel, поэтому push делается только после подтверждения пользователя и после того, как он выполнит нужную миграцию.
- В `vercel.json` для функций `api/expense-scan.js` и `api/expenses.js` увеличен `maxDuration`, потому что распознавание идёт дольше стандартных 10 секунд.

## Архитектура

- `index.html` и `admin.html` — самодостаточные страницы, в которых CSS и JS встроены inline. JS написан на vanilla в стиле ES5 (`var`, `function`), фреймворков нет. Из внешних ресурсов подключены только Google Fonts.
- В `vercel.json` включён `cleanUrls`, поэтому админка открывается по адресу `/admin`.
- `api/_lib.js` содержит общие помощники. Файлы с `_` в начале имени Vercel не публикует как маршруты.
  - Supabase вызывается напрямую через REST (`/rest/v1/…`), SDK нет. Ключ `sb_secret_…` передаётся только в `apikey`, а старый JWT service_role — ещё и в `Authorization: Bearer`.
  - Для админа используется stateless-токен вида `"<exp>.<HMAC-SHA256(exp, SESSION_SECRET)>"` со сроком 12 часов. Сессий в БД нет. Клиент хранит токен в `sessionStorage["vydyhai_token"]` и шлёт его в `Authorization: Bearer`.
- `api/lead.js` (POST) обрабатывает заявку:
  1. Если заполнено скрытое поле `website` (honeypot), отвечает `200` и ничего не сохраняет.
  2. Валидирует данные и обрезает их через `clean()`.
  3. Сохраняет заявку в Supabase с `source: "Сайт"` и `status: "Новая"`.
  4. Отправляет сообщение в Telegram (HTML parse_mode, все строки пропускаются через `escapeHtml`). Сбой Telegram только логируется: заявка уже сохранена.
- `api/login.js` проверяет пароль сравнением, устойчивым к атакам по времени. При неверном пароле ставит паузу 800 мс.
- `api/leads.js` открыт только для админа:
  - GET отдаёт всех клиентов для доски, свежие сверху, с фильтром `?status=`;
  - GET `?id=N` отдаёт клиента с полем `history` (из `lead_stage_history`);
  - POST `{name, phone, notes}` добавляет клиента вручную (`source: "Вручную"`, этап «Новая»);
  - PATCH `{id, status?, notes?}` меняет этап и/или заметки.
- Колонка этапа называется `status`. `comment` хранит текст посетителя из формы и не редактируется, `notes` — заметки админа.
- Историю этапов пишет триггер `leads_log_stage` в БД (после INSERT и UPDATE OF status), а не API. Поэтому в API её не дублируйте.
- В таблицах `leads` и `lead_stage_history` включён RLS без политик. Ключ anon/publishable доступа не имеет, работает только серверный ключ из Vercel.
- `admin.html` разбит на вкладки «Клиенты» и «Расходы» (`#expenses` в адресе открывает вторую). На вкладке «Клиенты» доска из колонок по этапам. Этап меняется через `<select>` на карточке или перетаскиванием мышью. Карточка клиента, форма «Добавить клиента» и экран проверки чека сделаны на `<dialog>`.

### Telegram Mini App (`app.html` → `/app`, `api/app.js`)
- Пользователь определяется только по initData. Браузер шлёт его в заголовке `Authorization: tma <initData>`, `telegramUser()` в `_lib.js` проверяет HMAC-SHA256 по документации Telegram (ключ = `HMAC("WebAppData", TELEGRAM_BOT_TOKEN)`) и возраст `auth_date` не больше 24 ч. Без валидного initData ответ 401. Имя, `telegram_id` и `username` из тела запроса не принимаются.
- Телефон необязателен. `requestContact` в `telegram-web-app.js` отдаёт подписанную строку `response`, сервер проверяет её через `verifyTelegramData()` (не старше 1 ч) и берёт номер, только если `contact.user_id` совпадает с проверенным пользователем. Иначе используется ручной ввод с проверкой `phoneOk`.
- Запись — это строка в `leads` с `source: "Telegram"`, `status: "Записан на консультацию"`, `telegram_id`, `telegram_username`, `consultation_at`. Уведомление админу уходит через `telegram()`, как в `api/lead.js`.
- Двойную запись не даёт допустить БД: уникальные частичные индексы `leads_consultation_slot_uniq` (один слот, кроме «Отказа») и `leads_telegram_active_uniq` (одна запись «Записан на консультацию» на пользователя). API распознаёт их по имени в тексте ошибки и отвечает 409, так же делает PATCH в `api/leads.js`.
- Слоты (`HOURS`, `DAYS_AHEAD`, `MIN_LEAD_MS` в `api/app.js`) считаются по Europe/Chisinau. `chisinauToUtc()` переводит местное время в UTC с учётом перехода на летнее и зимнее время. Ограничение `leads_consultation_hour_check` требует, чтобы время было ровно началом часа.
- Если страница открыта не в Telegram (`Telegram.WebApp.initData` пуст), показывается только заглушка, запросов к API нет. `BOT_USERNAME` в `app.html` задаёт ссылку на бота на заглушке.
- На бесплатном тарифе Vercel не больше 12 serverless-функций, поэтому GET и POST Mini App сделаны в одном `api/app.js`.

### Расходы
- Поток из двух шагов, чтобы до нажатия «Сохранить» ничего не сохранялось:
  1. `POST /api/expense-scan` отправляет файл в Gemini и возвращает поля. В БД и Storage ничего не пишет. Если это не чек, отвечает `422` с `not_receipt: true`. При лимите или перегрузке Gemini (429/5xx, таймаут) отвечает `503` с текстом «Попробуйте позже».
  2. `POST /api/expenses` получает файл повторно вместе с проверенными полями. Сначала загружает файл в Storage, потом создаёт строку. Если вставка не удалась, файл удаляется.
- Gemini вызывается через REST-интерфейс Interactions API (`/v1beta/interactions`), SDK нет. Заголовок `Api-Revision: 2026-05-20` закрепляет формат ответа: текст лежит в `steps[type=model_output].content[type=text]`. Ответ строго по JSON-схеме (`response_format`), `store: false`. Ответ модели дополнительно проверяется в `normalize()`.
- Устойчивость (`ATTEMPTS` в `api/expense-scan.js`): сначала `gemini-3.8-flash`, через 2 с ещё одна попытка на ней же, затем запасная `gemini-3.5-flash-lite`. Повтор и переход на запасную модель происходят только при временных ошибках (429/500/503/504, таймаут, сеть). При постоянной ошибке, например неверном ключе, функция сразу отвечает «не удалось». Все попытки вместе укладываются в `DEADLINE_MS` = 52 с, это меньше `maxDuration` 60 с. Если меняете таймауты, держите сумму в этих рамках. В лог пишется, какая модель ответила и за сколько.
- Файл передаётся как `{file: base64, type}`. `readFile()` в `_lib.js` проверяет тип, размер (не больше 3 МБ) и сигнатуру содержимого. Браузер уменьшает фото до 2000 px и пересохраняет в JPEG, PDF отправляет как есть. Всё ради лимита тела запроса Vercel 4,5 МБ.
- Оригиналы лежат в приватном bucket `receipts` по пути `ГГГГ-ММ/<uuid>.<ext>`. Политик на `storage.objects` нет. Ссылка на файл создаётся через `storageSignedUrl()` и живёт 5 минут.
- Итоги месяца считаются в `api/expenses.js` в целых копейках и отдельно по каждой валюте. Месяц определяется по дате чека (`expense_date`), а не по `created_at`.

## Что держать синхронным между файлами

- **Этапы воронки** `Новая` / `Связались` / `Записан на консультацию` / `Консультация проведена` / `Отказ` записаны в трёх местах: `STATUSES` в `api/_lib.js`, `STATUSES` в `admin.html` и `check`-ограничение `leads_status_check` в `supabase.sql`. В CSS `admin.html` у каждого этапа есть свой цвет через `[data-stage="…"]`. Новый этап добавляется отдельной миграцией.
- **Категории расходов** `Реклама` / `Печать материалов` / `Консультанты` / `Сервисы и подписки` / `Прочее` записаны в `CATEGORIES` в `api/_lib.js` (оттуда же берётся `enum` в JSON-схеме для Gemini), в `CATEGORIES` в `admin.html` и в `expenses_category_check` в `supabase.sql`. Если меняете категории, поправьте и описание категорий в `PROMPT` в `api/expense-scan.js`, а для работающей базы напишите миграцию.
- **Типы и размер файлов чеков**: `FILE_TYPES` и `MAX_FILE_BYTES` в `_lib.js`, `MAX_FILE` в `admin.html`, `expenses_file_type_check` и настройки bucket (`file_size_limit`, `allowed_mime_types`) в SQL.
- **Источники** `Сайт` / `Вручную` / `Telegram` задаются в `api/lead.js`, `api/leads.js` и `api/app.js`, а ограничение на них — `leads_source_check`. У бейджа источника в `admin.html` свой цвет через `.src[data-src="…"]`.
- **Темы консультаций** в Mini App (`TOPICS` в `api/app.js`) повторяют radio `name="type"` формы в `index.html`, кроме «Просто перезвонить».
- **Валидация формы** продублирована в `index.html` и `api/lead.js` с одинаковыми текстами ошибок: нужно имя и не меньше 6 цифр в телефоне (`phoneOk` в `_lib.js`). Согласие (`f-ok`) проверяется только на клиенте. Форма ручного клиента в `admin.html` и POST в `api/leads.js` проверяют то же самое, но тексты обращаются на «вы».
- **Имена полей**: в форме radio называется `name="type"`, а textarea — `name="msg"`, но JS отправляет их в API как `topic` и `comment`. В таком же виде они называются в БД.
- **Часовой пояс** `Europe/Chisinau` используется в `api/lead.js` (Telegram), `api/expenses.js` (текущий месяц) и `admin.html`. В админке дата всегда показывается с часами и минутами, чтобы совпадать с Telegram.

## Тексты

Весь интерфейс, сообщения API и комментарии в коде написаны на русском. На лендинге и в ошибках формы к посетителю обращаются на «ты», в админке — на «вы».
