# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## О проекте

«Выдыхай» — лендинг для подростков о вреде сигарет и вейпов. На нём есть форма заявки, CRM-админка с воронкой и уведомления в Telegram. Хостинг на Vercel, данные хранятся в Supabase. Подробная инструкция по развёртыванию (Supabase → Telegram-бот → GitHub → Vercel) и чек-лист проверки лежат в `README.md`.

## Сборка и запуск

- Сборки, линтера, тестов и npm-зависимостей нет. `package.json` нужен только для `"type": "module"`, чтобы `api/*.js` работали как ES-модули.
- На Vercel выбран Framework Preset **Other**. HTML отдаётся как статика, `api/*.js` работают как serverless-функции Node (`export default handler(req, res)`). `fetch` и `node:crypto` встроенные.
- Без переменных окружения API не работает: `env()` в `_lib.js` бросает ошибку. Нужны шесть переменных: `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `ADMIN_PASSWORD`, `SESSION_SECRET`. Настоящие значения задаются только в настройках Vercel. В `.env.example` хранится лишь образец без значений.
- Полная схема БД для новой установки лежит в `supabase.sql`. Изменения для уже работающей базы лежат в `migrations/NNN_*.sql`. И то и другое выполняют вручную в Supabase SQL Editor, причём миграцию — до загрузки кода, который на неё опирается. Меняя схему, обновляйте оба файла.
- Папка не является git-репозиторием. По README файлы загружаются на GitHub через веб-интерфейс.

## Архитектура

- `index.html` и `admin.html` — самодостаточные страницы, в которых CSS и JS встроены inline. JS написан на vanilla в стиле ES5 (`var`, `function`), фреймворков нет. Из внешних ресурсов подключены только Google Fonts.
- В `vercel.json` включён `cleanUrls`, поэтому админка открывается по адресу `/admin`.
- `api/_lib.js` содержит общие помощники. Файлы с `_` в начале имени Vercel не публикует как маршруты.
  - Supabase вызывается напрямую через REST (`/rest/v1/…`), SDK нет. Ключ `sb_secret_…` передаётся только в `apikey`, а старый JWT service_role — ещё и в `Authorization: Bearer`.
  - Для админа используется stateless-токен вида `"<exp>.<HMAC-SHA256(exp, SESSION_SECRET)>"` со сроком 12 часов. Сессий в БД нет. Клиент хранит токен в `sessionStorage["vydyhai_token"]` и шлёт его в `Authorization: Bearer`.
- `api/lead.js` (POST) обрабатывает заявку:
  1. Если заполнено скрытое поле `website` (honeypot), отвечает `200` и ничего не сохраняет.
  2. Валидирует данные и обрезает их через `clean()`.
  3. Сохраняет заявку в Supabase с `source: "Сайт"` и `status: "Новая"`.
  4. Отправляет сообщение в Telegram (HTML parse_mode, все строки пропускаются через `escapeHtml`). Сбой Telegram только логируется: заявка уже сохранена.
- `api/login.js` проверяет пароль сравнением, устойчивым к атакам по времени. При неверном пароле ставит паузу 800 мс.
- `api/leads.js` открыт только для админа:
  - GET отдаёт всех клиентов для доски, свежие сверху, с фильтром `?status=`;
  - GET `?id=N` отдаёт клиента с полем `history` (из `lead_stage_history`);
  - POST `{name, phone, notes}` добавляет клиента вручную (`source: "Вручную"`, этап «Новая»);
  - PATCH `{id, status?, notes?}` меняет этап и/или заметки.
- Колонка этапа называется `status`. `comment` хранит текст посетителя из формы и не редактируется, `notes` — заметки админа.
- Историю этапов пишет триггер `leads_log_stage` в БД (после INSERT и UPDATE OF status), а не API. Поэтому в API её не дублируйте.
- В таблицах `leads` и `lead_stage_history` включён RLS без политик. Ключ anon/publishable доступа не имеет, работает только серверный ключ из Vercel.
- `admin.html` показывает доску из колонок по этапам. Этап меняется через `<select>` на карточке или перетаскиванием мышью. Карточка клиента и форма «Добавить клиента» сделаны на `<dialog>`.

## Что держать синхронным между файлами

- **Этапы воронки** `Новая` / `Связались` / `Записан на консультацию` / `Консультация проведена` / `Отказ` записаны в трёх местах: `STATUSES` в `api/_lib.js`, `STATUSES` в `admin.html` и `check`-ограничение `leads_status_check` в `supabase.sql`. В CSS `admin.html` у каждого этапа есть свой цвет через `[data-stage="…"]`. Новый этап добавляется отдельной миграцией.
- **Источники** `Сайт` / `Вручную` задаются в `api/lead.js` и `api/leads.js`, а ограничение на них — `leads_source_check`.
- **Валидация формы** продублирована в `index.html` и `api/lead.js` с одинаковыми текстами ошибок: нужно имя и не меньше 6 цифр в телефоне (`phoneOk` в `_lib.js`). Согласие (`f-ok`) проверяется только на клиенте. Форма ручного клиента в `admin.html` и POST в `api/leads.js` проверяют то же самое, но тексты обращаются на «вы».
- **Имена полей**: в форме radio называется `name="type"`, а textarea — `name="msg"`, но JS отправляет их в API как `topic` и `comment`. В таком же виде они называются в БД.
- **Часовой пояс** `Europe/Chisinau` используется в `api/lead.js` (Telegram) и `admin.html`. В админке дата всегда показывается с часами и минутами, чтобы совпадать с Telegram.

## Тексты

Весь интерфейс, сообщения API и комментарии в коде написаны на русском. На лендинге и в ошибках формы к посетителю обращаются на «ты», в админке — на «вы».
